# Моя шпаргалка Git

| Команда | Що робить — своїми словами | Коли я її використаю |
|---|---|---|
| `git clone` | Завантажує репозиторій з GitHub на комп'ютер разом з усією історією | Один раз на початку, щоб отримати свою копію репо |
| `git status` | Показує, які файли змінені, які вже додані до коміту, а які Git ще не відстежує | Перед `add` і `commit`, щоб зрозуміти, що зараз відбувається |
| `git diff` | Показує, що саме змінилося у файлах, рядок за рядком | Щоб перевірити свої зміни перед тим, як їх додати |
| `git add` | Відбирає зміни в наступний коміт (кладе їх в індекс) | Коли зміни у файлі готові і я хочу їх зберегти |
| `git commit` | Фіксує відібрані зміни як нову точку в історії з описом | Коли закінчила частину роботи |
| `git push` | Відправляє мої коміти на GitHub | Наприкінці роботи, щоб усе було онлайн і викладач бачив |
| `git log` | Показує історію комітів: хто, коли і з яким повідомленням | Щоб подивитися, що вже зроблено, або знайти потрібний коміт |
| `git branch` | Показує список гілок і зірочкою позначає ту, де я зараз. З назвою створює нову гілку | Щоб перевірити, у якій я гілці, або зробити нову |
| `git checkout -b` | Створює нову гілку й одразу переходить на неї | Коли хочу спробувати щось окремо, не чіпаючи `master` |
| `git merge` | Забирає зміни з іншої гілки в поточну | Коли робота в гілці готова і її треба повернути в `master` |

## Передбачення

Стан перед перевіркою: в останньому коміті `eksperyment.txt` має лише `Рядок 1`, в індексі (після `add`) — `Рядок 1` і `Рядок 2`, а у самому файлі — всі три рядки.

### 1. У якому розділі `git status` покаже `eksperyment.txt`?

Передбачення: в обох одразу. У «Changes to be committed» — бо версія з рядком 2 вже в індексі, і в «Changes not staged for commit» — бо рядок 3 ще не доданий.

Git показав: `eksperyment.txt` справді є в обох розділах — `modified` і в «Changes to be committed», і в «Changes not staged for commit». Я вгадала, бо Git зберігає окремо три версії файлу: в останньому коміті, в індексі й на диску — і порівнює їх попарно.

### 2. Що покаже `git diff`, а що — `git diff --staged`?

Передбачення: `git diff` порівнює файл з індексом, тому покаже `+Рядок 3`. `git diff --staged` порівнює індекс з останнім комітом, тому покаже `+Рядок 2`.

Git показав: `git diff` — `+Рядок 3`, `git diff --staged` — `+Рядок 2`. Я вгадала, бо кожна команда порівнює свою пару версій: диск з індексом і індекс з комітом.

### 3. Що потрапить у коміт без `add`? Що покаже `git status` після нього?

Передбачення: у коміт піде тільки те, що в індексі, тобто `Рядок 1` і `Рядок 2`. `Рядок 3` залишиться незакоміченим. Після коміту `git status` покаже `eksperyment.txt` лише в «not staged», а ще там буде `shpargalka.md`, бо я дописала в неї передбачення. `git show HEAD` покаже `+Рядок 2`.

Git показав: коміт «Експеримент: коміт без add» — `1 file changed, 1 insertion(+)`, `git show HEAD` — лише `+Рядок 2`, а `git status` після коміту — `eksperyment.txt` і `shpargalka.md` у «not staged». Я вгадала, бо `commit` бере не файл з диска, а те, що лежить в індексі.
